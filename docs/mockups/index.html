Decisões de interface

  • Prazo e quantidades vêm antes das ações de desmembrar/remessar.
  • O botão “+” reduz a poluição visual e mantém o formulário acessível.
  • Cada ação bem-sucedida exibe confirmação textual (não só cor).
  • A remessa é claramente “previsão”; a entrega realizada é outro registro.
  • Progresso com percentual textual e cor por estado real.

5. Estados de interface

Toda tela deve cobrir carregando, vazio, sucesso e erro de forma acessível.

Carregando

Carregando…Anunciado por role="status".

Vazio

Sem pedidos. Nenhum pedido encontrado com os filtros atuais.

Sucesso

Pedido atualizado com sucesso.

Erro

Não foi possível atualizar o pedido. Verifique sua conexão e tente novamente.

6. Fluxo de navegação

Abertura e retorno com contexto preservado (filtros na URL).

Login → Vendas / Pedidos → Detalhe do pedido → Desmembrar → + Remessa → Confirmar remessa → ← Voltar para os pedidos (filtros mantidos)
Operador: fila → Executar atividade → Registrar execução/ocorrência → Ordem de produção → Imprimir
Gerente: painel/alertas → Pedidos → Detalhe → Exceção de entrega (quando aplicável)
