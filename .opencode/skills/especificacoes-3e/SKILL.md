# Especificações 3E

Usar junto de `tlc-spec-driven`.

1. Ler `.specs/STATE.md`.
2. Ler `docs/decisoes.md` e os documentos do domínio necessários.
3. Identificar HU/RF/RN/RFN afetados.
4. Tornar critérios de aceitação testáveis.
5. Registrar suposições/lacunas em vez de inventar comportamento.
6. Mapear cada critério a testes.
7. Validar implementação contra os critérios antes de concluir.

Se houver conflito de método, seguir Tech Leads Club. Se houver dúvida de fato de negócio, os documentos do projeto são a fonte e a lacuna deve ser explicitada.
